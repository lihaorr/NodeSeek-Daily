# Lottery reply design

User settings: identify new lottery/giveaway posts, prepare ten Chinese participation comments, at most ten successful replies per Asia/Shanghai day, no new eligible posts means no replies.

Use public RSS only for the default no-browser preview. Browser discovery in live and explicit search-preview modes scans up to five newest pages and two pages of the authenticated search term 抽奖, with configurable bounded page/term counts. Deduplicate by canonical post ID across pages, sources and state, then inspect up to forty original posts. Never infer publication from list activity timestamps. Read the original `.content-item[id="0"] .date-created time[datetime]`, title identity and article; validate both explicit deadlines and official lucky-link timestamps. New means published within 24 hours and not previously processed. Exclude ended draws, lottery software discussions, external-only participation and specified reply formats. The original must explicitly allow a general reply; ambiguity is skipped. This is bounded discovery, not guaranteed full-site or full-text coverage.

Retain Selenium and installed-Chrome version matching. Default RSS preview never starts a browser. Explicit search-preview requires Cookie and numeric forum user ID but never checks in, fills an editor, publishes or writes state. Space browser requests three seconds apart, do not retry searches, stop at empty/end/repeated pages, and report configured limits. Cross-origin redirects (including guest Google search), query-changing pagers, login failures, rate limits and unexpected structures fail visibly. Live mode requires an explicit flag. Browser challenges stop actions; no bypass is introduced. Check-in runs independently before discovery; daily quota exhaustion skips discovery. Ten default comments are each four Chinese characters.

Store per-post pending/confirmed/unknown outcomes permanently. Reserve and checkpoint before each click; only a newly visible exact reply by the configured account counts as confirmed. Unknown submissions stop the batch and occupy quota until reviewed. Successful records count against the Beijing dates crossed during submission. Persistent state uses atomic local JSON or GitHub Contents API with SHA conflict checks and a workflow-wide concurrency group. Never silently reset corrupt state. Migrate only the verified empty version-1 legacy state.

Development does not publish forum replies, enable scheduled workflows, or merge into main. Deliver a tested feature branch and configuration documentation.
